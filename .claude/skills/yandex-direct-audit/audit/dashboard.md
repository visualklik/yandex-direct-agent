# Визуальный отчёт аудита: принципы вёрстки

Генератор — `dashboard.py`. Один самодостаточный HTML: ни шрифтов, ни библиотек, ни запросов
наружу. Файл можно переслать в мессенджере, открыть офлайн и распечатать в PDF.

```bash
python3 fetch.py --days 30 --out-dir data          # все отчёты одной командой
python3 urls.py --snapshot snapshot.json --out urls.json
python3 dashboard.py --snapshot snapshot.json --reports data --urls urls.json \
    --target-cpa 500 --account "Клиент" --period "20.07 — 18.08.2026" \
    --out audit.html
```

`--reports` берёт из каталога файлы с фиксированными именами (`campaigns.tsv`, `days.tsv`,
`placements.tsv`, `segment.tsv`, `targeting.tsv`, `matchtype.tsv`, `traffic.tsv`,
`device.tsv`, `gender.tsv`, `age.tsv`, `geo.tsv`, `queries.tsv`). Отдельные флаги `--campaigns/--placements/--days` остаются для ручной сборки.

Обязателен только `--snapshot`. Отчётов нет — соответствующие блоки не рисуются, а не заполняются
заглушками. `--anonymize` заменяет названия кампаний на «Кампания N» — для демонстраций и портфолио.

## Порядок блоков — от решения к данным

Типовая ошибка отчётов: инвентаризация сверху, план правок в самом низу. Читатель прокручивает
восемь таблиц, прежде чем узнает, что ему делать. Здесь наоборот:

1. **Вердикт** — оценка 0–100, одна фраза о состоянии аккаунта, 4 строки сути, KPI-полоса.
2. **Что делать первым** — план правок сразу, карточками P0/P1/P2, с ожидаемым эффектом справа.
3. **Где деньги** — расход по кампаниям, доля Поиск/Сети, динамика по дням.
4. **Срезы эффективности** — упоминание бренда, Поиск/сети, тип таргетинга, тип соответствия,
   устройства, пол, возраст, города, объём трафика на Поиске.
5. **Поисковые запросы** — топ-30 по расходу и доля расхода без конверсий.
6. **Площадки РСЯ** — кривая концентрации, порог значимости, вердикт, список кандидатов.
7. **Посадочные страницы** — сколько адресов проверено, сколько битых, сколько из них в показах.
8. **Настройки** — слепок значений таблицей.

В срезах CPA подсвечен относительно целевого: красным — дороже полутора целевых, зелёным —
дешевле цели. Подсветка включается только когда целевой CPA задан явно (`--target-cpa`),
иначе сравнивать не с чем и цвет вводил бы в заблуждение. Категории API переводятся
(`GENDER_FEMALE` — «Женщины», `AGE_35_44` — «35–44»); словарь — `LABELS` в `dashboard.py`.
Города обрезаются до десяти, остальное сворачивается в строку «остальные (N)»: в гео-отчёте
сотни строк, и хвост из единичных кликов только мешает.

Срезы идут **каждый на всю ширину блока, один под другим**, а не плиткой в два-три столбца.
В узкой колонке таблица из шести числовых столбцов уезжает в горизонтальный скролл, и сравнивать
строки глазами становится нельзя. Полная ширина стоит вертикальной прокрутки, но читается без
единого скролла внутри карточек.

Бренд считается на своей стороне: среза «упоминание бренда» в API нет, поэтому запросы делятся
по списку слов из `--brands`. Список берётся у клиента и включает опечатки и латиницу
(«морквест», «more kvestov»): по одному правильному написанию половина брендового спроса
уедет в небренд. Без `--brands` карточка не рисуется — врать про долю бренда хуже, чем молчать.

Объём трафика — шкала Директа, где 100 это самое верхнее место, а не проценты и не CTR.
В карточке он идёт с показами и расходом рядом: низкий объём при заметном расходе означает
дешёвые блоки и недобор охвата.

Кольцо оценки — SVG, а не `conic-gradient`: нужен круглый срез линии (`stroke-linecap: round`)
и цвет дуги по уровню (зелёная от 80, янтарная от 55, красная ниже). Цифра и подпись лежат
в абсолютно спозиционированном слое поверх кольца — так они центрируются по геометрическому
центру круга, а не по потоку.

Правило: чем ниже блок, тем он подробнее и тем менее обязателен для прочтения. Сырые таблицы
спрятаны в `<details>` — топ виден сразу, хвост по клику.

## Оценка аккаунта

Балл считается от находок: критичная −14, важная −6, улучшение −2, пол ограничен снизу пятёркой.
Это не научная метрика, а якорь для разговора: «58 из 100» запоминается и обсуждается,
а список из девяти пунктов — нет. Формулировка рядом обязательна: «здоровый» (80+),
«рабочий, но с потерями» (55–79), «требует вмешательства» (ниже).

## Графика — только та, что несёт вывод

Четыре типа, все — inline SVG или CSS, без библиотек:

| Элемент | Что показывает | Зачем |
|---|---|---|
| Горизонтальные бары | расход по кампаниям, подпись — CPA | видно и объём, и качество одновременно |
| Кольцо | Поиск против сетей | одна цифра, которую все спрашивают первой |
| Спарклайн | расход по дням линией, конверсии столбиками | расхождение форм = повод копать |
| Кривая концентрации | накопленная доля расхода по площадкам | доказывает, что чистить надо верх списка, а не хвост |

Чего сознательно нет: круговых диаграмм на 12 сегментов, 3D, градиентных заливок данных,
цветового кодирования там, где хватает порядка строк.

## Цвет как значение, а не как украшение

Три семантических цвета и ничего сверх: P0 — красный, P1 — янтарный, P2 — синий, норма — бирюзовый
акцент. Красный не используется для оформления заголовков, янтарный — для «просто важно».
Если элемент цветной, у цвета есть смысл, который читается из легенды или тега рядом.

Тема следует системной: полная палитра в `:root`, переопределение в
`@media (prefers-color-scheme: dark)` под `:root:not([data-theme="light"])`. Фон `body` задан
токеном явно — иначе страница на тёмной теме просвечивает.

## Печать

`@media print` убирает навигацию, раскрывает `<details>`, снимает тени и запрещает разрыв секций.
PDF снимается так:

```bash
chromium --headless --disable-gpu --no-sandbox \
  --print-to-pdf=audit.pdf --no-pdf-header-footer audit.html
```

## Язык интерфейса, а не язык API

Отчёт читает человек, который настраивает кампании в интерфейсе Директа. `WB_MAXIMUM_CLICKS`
и `PAY_FOR_CONVERSION` ему ничего не говорят — в интерфейсе это «Максимум кликов»
и «Максимум конверсий с оплатой за конверсии». Словарь кодов — `STRATEGY_NAMES` в `dashboard.py`,
неизвестный код показывается как есть, чтобы отчёт не врал.

Рядом с названием — ограничения стратегии одной строкой: цена конверсии, недельный бюджет,
ДРР, цель. Это ровно те цифры, которые человек ищет в карточке кампании.

Отдельно про `GoalId`. У целей Метрики идентификаторы восьми-девятизначные; короткий id
(например 13) клиентской цели не соответствует. Что за ним стоит, из API не видно — справка
упоминает «вовлечённые сессии» как значение по умолчанию, но только для стратегий
«Максимум кликов» (`docs/strategies/priority-goals.md`), а короткий id встречается и в других.
Поэтому в отчёте такая цель помечается «проверить в интерфейсе», а не называется наугад:
догадка в отчёте для клиента неотличима от факта и стоит доверия ко всему документу.

## Тексты

- Заголовок блока — что это. Подзаголовок (`.lede`) — как читать график. Без подзаголовка
  диаграмма превращается в украшение.
- Каждая находка: что не так → где (объекты) → эффект правки. Три части, ни одной лишней.
- Вывод пишется словами даже там, где он отрицательный: «кандидатов на запрет нет, хвост —
  статистический шум» полезнее пустой таблицы.
- Числа с неразрывными пробелами, проценты до одного знака, деньги без копеек.
- Склонения считаются (`plural()`), «1 находки» в отчёте для клиента недопустимо.

## Что можно добавить под конкретный проект

Блоки, которые генератор пока не рисует, но данные для них снимаются тем же способом:
поисковые запросы (топ по расходу с пометкой мусорных), гео-хвост, устройства,
объявления с битыми ссылками, история изменений. Добавлять по одному и только если
у блока есть вывод — иначе отчёт распухает и его перестают читать.
