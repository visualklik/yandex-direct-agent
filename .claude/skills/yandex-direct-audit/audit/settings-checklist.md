# Чеклист настроек: ошибка → как обнаружить → правка

Прогонять механически по всем уровням. Колонка «Обнаружение» — что именно смотреть в слепке
(`collect.py` кладёт всё в один JSON) или в отчёте. Имена полей API проверены на живом аккаунте,
август 2026 — `api-collect.md`.

Приоритет находки = серьёзность × доля расхода кампании. Одна и та же ошибка в кампании
с 3% и с 60% расхода — разные строки в отчёте.

---

## 1. Аккаунт

| Ошибка | Обнаружение | Правка |
|---|---|---|
| Баланс меньше недельных бюджетов — кампании встанут посреди недели | сумма `WeeklySpendLimit` по активным кампаниям против остатка на счёте | пополнение — только сам пользователь |
| Разные кампании конкурируют за одни запросы | пересечение ключей между кампаниями (см. блок 4) | развести семантику или объединить |
| Общий счёт выключен при нескольких кампаниях | `Settings.SHARED_ACCOUNT_ENABLED = NO` | включить, иначе бюджет заперт в кампаниях |
| Нет уведомлений о событиях | `Notification` (Email, SmsEvents) пуст | включить хотя бы «кампания остановлена», «закончились деньги» |
| Архивных и остановленных кампаний больше, чем работающих | `State` по всем кампаниям | не ошибка, но признак свалки: почистить перед аудитом структуры |

## 2. Кампания

### 2.1 Тип и структура

| Ошибка | Обнаружение | Правка |
|---|---|---|
| Поиск и сети в одной кампании | `BiddingStrategy.Search` и `.Network` оба не `SERVING_OFF`/`NETWORK_DEFAULT` в старой ТГК | разделить: разные ставки, разные объявления, разная аналитика |
| Мастер кампаний вместо полноценной там, где нужен контроль | кампания есть в отчётах, но `campaigns.get` её не возвращает — см. `api-collect.md` | в Мастере нельзя запретить площадки и править через API; при заметном бюджете переносить в обычную кампанию |
| Кампания создана давно и не переведена в ЕПК, хотя объявления уже комбинаторные | `Type` + тип объявлений `RESPONSIVE_AD` | оценить перевод, не ломая накопленную статистику |

### 2.2 Стратегия и бюджет

| Ошибка | Обнаружение | Правка |
|---|---|---|
| Недельный бюджет не даёт 10 конверсий/нед — стратегия не обучится | `WeeklySpendLimit` / целевой CPA < 10 | поднять бюджет или объединить кампании; иначе автостратегия слепа |
| Целевой CPA задан ниже рыночного — мало показов | целевой CPA против фактического CPA по отчёту | поднимать шагами ≤20–30%, ждать перестройки |
| Оплата за конверсии на цели, набирающей <10 конверсий/нед | `BiddingStrategyType` + статистика цели | сменить цель или модель оплаты |
| Частые правки сбивают обучение | журнал изменений (`docs/campaigns/logs.md`) | «дни без правок» < 14 — выводы об эффекте не делать |
| Дневной бюджет режет показы в конверсионные часы | `DailyBudget` + `Settings.DAILY_BUDGET_ALLOWED = YES`, режим «стандартный/распределённый» | распределённый режим или снятие ограничения |
| Перенос остатка не учтён при разборе перерасхода | `WeeklyBudgetRollover` | не правка, а поправка к анализу: до 30% остатка, потолок 130% недели |

### 2.3 Аналитика в кампании — самый частый источник тихих потерь

| Ошибка | Обнаружение | Правка |
|---|---|---|
| Счётчик Метрики не привязан — стратегия оптимизируется вслепую | `CounterIds = null` | привязать; без счётчика конверсионные стратегии бессмысленны |
| Битый счётчик в списке | **только глазами**: в карточке кампании такой счётчик подписан красным «Счётчик не найден». API отдаёт `CounterIds` без признака валидности | убрать из кампании: счётчик удалён или доступ к нему потерян, данные с него не идут, а цели с него в стратегии молча не работают |
| Не заданы цели | цели нет **ни** в `PriorityGoals`, **ни** в `BiddingStrategy.*.GoalId` | задать цель-деньги и её ценность |
| Цель-микроконверсия как ключевая («просмотр 2 страниц») | `PriorityGoals` + определение цели в Метрике | заменить на макроцель; микро — только если макро <10/нед |
| Модель атрибуции в стратегии не та, по которой оценивают | `AttributionModel` (`AUTO`, `LSC`, `FC`, …) против модели в отчётах | зафиксировать одну; иначе расхождения объясняются «магией» |
| Разметка ссылок выключена — источник неотличим в Метрике | `Settings.ADD_METRICA_TAG = NO` при отсутствии UTM в ссылках | включить или проставить UTM (`docs/statistics/url-tags.md`) |
| Мониторинг сайта выключен — деньги льются при лежащем сайте | `Settings.ENABLE_SITE_MONITORING = NO` | включить (`docs/campaigns/site-monitoring.md`) |

### 2.4 Таргетинги и ограничения

| Ошибка | Обнаружение | Правка |
|---|---|---|
| Расширенный геотаргетинг тянет чужие регионы | `Settings.ENABLE_AREA_OF_INTEREST_TARGETING = YES` + отчёт по регионам | для локального бизнеса с офлайн-точкой обычно выключать; для доставки — оставлять |
| Гео шире, чем география работы | `RegionIds` группы против реальной зоны продаж | сузить, минус-регионы через `RestrictedRegionIds` |
| Расписание не совпадает с приёмом заявок | `TimeTargeting` против графика колл-центра | либо выключить показ, либо корректировка −%, либо форма вместо звонка |
| Часовой пояс не тот | `TimeZone` | иначе расписание и дневные отчёты смещены |
| Корректировки −100% на уровне кампании перебиты корректировкой на группе | `bidmodifiers` по обоим уровням | продублировать корректировку в группу — групповая полностью игнорирует кампанийную в своей категории |
| Нет корректировки по устройствам при разном CPA | `bidmodifiers` + отчёт по устройствам | ставить только по статзначимой разнице |
| Не исключены свои сотрудники / офис | `BlockedIps` пуст, в статистике заметен офисный трафик | добавить IP (`docs/campaigns/disable-ip.md`), но не увлекаться: динамические IP |
| Минус-слов нет нигде | пусты `NegativeKeywords` кампании, `NegativeKeywords` всех её групп и `NegativeKeywordSharedSetIds` обоих уровней | собрать стоп-лист по отчёту запросов; на Поиске это важно, в сетях эффект слабее |
| Минусовка размазана по группам | минус-слова только на уровне групп | общий стоп-лист — на кампанию или в библиотеку, точечный — в группу; дублирование в 40 группах не поддерживается |

### 2.5 Тонкие настройки, которые обычно забывают

| Настройка | Значение по умолчанию | Когда менять |
|---|---|---|
| `CAMPAIGN_EXACT_PHRASE_MATCHING_ENABLED` | NO | YES — если нужны показы строго по фразе без словоформ-расширений; резко сужает охват |
| `RelevantKeywords` (доп. релевантные фразы) | выкл/огранич. | включено на Поиске = источник нецелевых запросов; проверять по отчёту запросов |
| `EXCLUDE_PAUSED_COMPETING_ADS` | NO | YES — точнее прогноз позиций, на автостратегиях эффект небольшой |
| `MAINTAIN_NETWORK_CPC` | NO | YES — удерживать цену клика в сетях |
| `ENABLE_EXTENDED_AD_TITLE` | YES | выключать нет причин: домен подтягивается в заголовок |
| `ENABLE_COMPANY_INFO` | YES | подтягивает данные организации из Справочника — проверить, что организация та |
| `ALTERNATIVE_TEXTS_ENABLED` | NO | YES — Директ генерирует альтернативные тексты; проверять качество вручную |
| `ADD_OPENSTAT_TAG` | NO | только если аналитика на Openstat |

## 3. Группы

| Ошибка | Обнаружение | Правка |
|---|---|---|
| В группе одно объявление — нечего ротировать | число `ads` c `State = ON` на группу | 2–3 варианта либо одно комбинаторное с 3–7 заголовками |
| Комбинаторные объявления-клоны | `Titles`/`Texts` длины 1 у нескольких объявлений группы **с одинаковым `Href`** (без UTM) | схлопнуть в одно комбинаторное — рецепт в `../yandex-direct/updates/api-responsive-ads.md` |
| Больше 3 неархивных комбинаторных в группе (наследие) | подсчёт по группам | XLS-загрузка такой кампании невозможна, только API |
| Группа не показывается | `ServingStatus = RARELY_SERVED` | расширить семантику, поднять ставку/бюджет |
| Разные посадочные внутри одной группы | `Href` объявлений группы | либо разбить группу, либо это осознанно — но схлопывать такие объявления нельзя |
| Гео группы противоречит гео кампании | `RegionIds` обоих уровней | привести в порядок |

## 4. Ключевые фразы и запросы

| Ошибка | Обнаружение | Правка |
|---|---|---|
| Дубли фраз между группами и кампаниями | нормализовать ключи (lowercase, снять операторы, отсортировать слова) и искать повторы | оставить в одной группе; дубли конкурируют друг с другом |
| Минус-слово перекрывает собственный ключ | пересечение слов ключа со списком минус-слов | снять минус-слово или уточнить оператором |
| Фразы без минус-слов вообще | пустые `NegativeKeywords` на всех уровнях + отчёт запросов. **Только там, где есть поисковый запрос** — см. оговорку ниже | собрать стоп-лист по отчёту «Поисковые запросы» |

Оговорка: минус-слова отсекают поисковый запрос. Там, где запроса нет, отсекать нечего — и пустой список **не является находкой**:

- кампании только на сети: `BiddingStrategy.Search.BiddingStrategyType = SERVING_OFF` (РСЯ, ретаргетинг, кампании на аудитории);
- смарт-баннеры (`SMART_CAMPAIGN`) — показ по фиду и интересам;
- медийные (`CPM_*`) и реклама приложений (`MOBILE_APP_CAMPAIGN`).

В таких кампаниях нецелевой трафик режется площадками и корректировками, а не минусовкой. Писать про отсутствие минус-слов в отчёте по ним — шум, который обесценивает остальные находки. Реализовано в `checks.py`, функция `search_serves()`.
| Бренд смешан с небрендом в одной кампании | доля брендовых запросов в расходе (срез по списку слов бренда) | разводить: бренд дёшев и маскирует убыточность небренда, а автостратегия учится на лёгких конверсиях |
| Мусорные запросы в расходе | отчёт «Поисковые запросы» за 30–90 дней, строки с расходом и 0 конверсий | минусовать блоками, показывать список на одобрение до применения |
| Слишком длинные/узкие фразы | `Productivity` (продуктивность фразы) низкая, `StatisticsSearch` почти нулевая | переписать, объединить |
| Автотаргетинг тянет нецелевое | срез `CriterionType` в отчёте: доля расхода `AUTOTARGETING` и его CPA против `KEYWORD`; плюс `AutotargetingCategories` на ключе/группе | отключать конкретные категории, а не автотаргетинг целиком; если CPA автотаргетинга кратно хуже семантики — снижать его долю |
| Ставки заданы вручную под автостратегией | `Bid`/`ContextBid` при автостратегии | значения игнорируются — не тратить время на их правку |

## 5. Объявления

| Ошибка | Обнаружение | Правка |
|---|---|---|
| Все ссылки на главную | `Href` у всех объявлений одинаков | вести на страницу конкретного товара/услуги; быстрые ссылки не трогать |
| Битые посадочные | `audit/urls.py`: коды 404/410/5xx по всем уникальным адресам | чинить на сайте или менять ссылку; в первую очередь те, что стоят в работающих объявлениях |
| Редирект на главную | адрес отвечает 200, но после редиректов путь схлопнулся в `/` | страница удалена или переименована: клик оплачен, а пользователь не там, куда шёл |
| Мягкая 404 | HTTP 200, но в заголовке или тексте «страница не найдена» | самый незаметный случай: код нормальный, страницы нет |
| Битые быстрые ссылки | те же проверки по адресам из `sitelinks.get` | ссылки на удалённые соцсети и акции живут в наборах годами |
| UTM потеряны или неконсистентны | разбор query-строки `Href` | привести к одной схеме; при массовой правке ссылок хвост сохранять |
| Нет быстрых ссылок / уточнений / визитки / цены | `SitelinkSetId`, `AdExtensions`, `PriceExtension`, `TrackingPhoneId` пусты | заполнять: занимают место в выдаче, повышают CTR |
| В РСЯ у объявления одна картинка | `AdImages` длины 1 | до 5 изображений; при схлопывании клонов переносить явно |
| Нет широкоформатных изображений | `adimages.get`: доля `Type = WIDE` в библиотеке | справка рекомендует два варианта — стандартный и широкоформатный, иначе часть площадок недобирается (`docs/efficiency/images.md`); требования и смарт-центры — `../yandex-direct/action/rsya-creatives.md` |
| Заголовок не содержит запрос | сверка `Titles` с топ-запросами группы | переписать под кластер |
| Объявления не проходят модерацию | `Status = REJECTED` | `docs/moderation/` |
| Незаполненная организация/телефон | `BusinessId`, `TrackingPhoneId` | подключить Справочник, коллтрекинг |

## 6. Аналитика и учёт (вне Директа, но ломает всё)

| Ошибка | Обнаружение | Правка |
|---|---|---|
| Счётчик стоит не на всех страницах | Метрика: сравнение визитов и кликов, расхождение >15% | чинить установку |
| Цели ведут не туда (спасибо-страница без реального заказа) | определение цели в Метрике | пересобрать по воронке |
| Звонки не считаются | нет коллтрекинга при телефонном спросе | подключить (`docs/efficiency/check-list.md`) |
| Офлайн-продажи не возвращаются в Директ | нет офлайн-конверсий | `docs/statistics/conversions.md` |
| Ecommerce не передаёт доход — ДРР и ROI считать нечем | `Доход` в отчётах пуст | настроить Ecommerce или задать ценность вручную |
| Данные CRM расходятся с Директом в разы | сверка выгрузок | разные атрибуции/цели/окна — сверять до выводов |

## 7. Быстрые автопроверки

Что имеет смысл гонять скриптом на каждом аудите:

1. Кампании с `CounterIds = null` при конверсионной стратегии — критично всегда.
2. Кампании без цели: пусто и в `PriorityGoals`, и в `GoalId` стратегии.
3. `ENABLE_SITE_MONITORING = NO` — включается за секунду, страхует от слива на лежащем сайте.
4. `ADD_METRICA_TAG = NO` при ссылках без UTM.
5. Все `Href` — HTTP-код (404 и редиректы на главную).
6. Дубли нормализованных ключей: внутри кампании между группами (конкуренция) и между кампаниями (проверить, разные ли площадки).
7. Группы с одним активным объявлением.
8. Группы, где несколько `RESPONSIVE_AD` с одним заголовком **и одинаковым URL** (кандидаты на схлопывание).
9. Кампании, где `ExcludedSites` длиннее 300 доменов — почти всегда карго-культ, проверить эффект.
10. Недельный бюджет / целевой CPA < 10 конверсий.
11. Продуктивность фраз ниже 5 (`Productivity`) — переписать или объединить.
12. Группы, где больше 15 активных фраз: одно объявление не может быть релевантно всем.
13. Наборы быстрых ссылок короче четырёх ссылок и объявления без набора вовсе.
14. Библиотечные наборы минус-слов не используются ни одной кампанией.
15. Остановленных кампаний больше, чем работающих, — аккаунт пора чистить.
16. Библиотека изображений: есть ли широкоформатные, сколько непривязанных.
17. Счётчики, стоящие лишь в одной кампании, когда остальные разделяют общий набор, — повод
    открыть карточку и посмотреть, нет ли «Счётчик не найден».

Полный реестр проверок с идентификаторами, категориями и серьёзностью — в самом `checks.py`
(константа `CHECKS`), правила подсчёта балла — `scoring.md`, комплаенс — `compliance.md`.

Что скриптом не проверяется и остаётся ручным: валидность счётчиков Метрики (API отдаёт только
идентификаторы), содержание целей, качество текстов объявлений, соответствие посадочной запросу.

## 8. Ложные срабатывания: где настройка лежит не там, где её ищут

Проверено на боевом аккаунте — каждый пункт стоил ложной находки в отчёте:

| Кажется | На самом деле |
|---|---|
| «Не заданы цели»: `PriorityGoals = null` | При **одной** цели она лежит внутри стратегии: `BiddingStrategy.Search.PayForConversion.GoalId`. `PriorityGoals` заполняется, только когда целей несколько и у них заданы ценности. Проверять оба места |
| «Нет минус-слов»: пуст `NegativeKeywords` кампании | Во-первых, минусовка может целиком жить в группах или в наборах библиотеки — складывать три уровня. Во-вторых, для кампаний без поискового запроса (сети, смарт-баннеры, медийка, приложения) минус-слова не нужны в принципе: пустой список — норма |
| «Объявления-клоны» | Несколько объявлений с одним заголовком — не всегда клоны: при разных посадочных схлопывать нельзя. Группировать по `Href` без UTM |
| «Одно изображение» | Для кампаний, где сети выключены (`Network.BiddingStrategyType = SERVING_OFF`), изображения вообще не нужны |
| «Разметка выключена» | `ADD_METRICA_TAG = NO` не проблема, если UTM уже прописаны в ссылках. Смотреть на `Href` объявлений |
| «Счётчики привязаны — значит всё в порядке» | `CounterIds` возвращает список идентификаторов и ничего не говорит об их работоспособности. Удалённый или недоступный счётчик выглядит в API так же, как рабочий. Проверяется только в интерфейсе — на боевом аккаунте три из пяти счётчиков в кампании оказались с пометкой «Счётчик не найден» |

Общее правило: **находка объявляется только после проверки всех уровней, где настройка может
лежать.** Ложная находка дороже пропущенной: она стоит доверия ко всему отчёту.
