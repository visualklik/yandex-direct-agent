# Аудит настроек Яндекс Директа

Третий скилл в связке:

| Скилл | Вопрос, на который отвечает |
|---|---|
| `yandex-direct` | как настроить и создать |
| `yandex-direct-analyst` | что говорят цифры |
| **`yandex-direct-audit`** | **что настроено неправильно и что с этим делать** |

Разделение простое: аналитик смотрит в статистику, аудитор — в конфигурацию. Пересечение одно
— «сливающие срезы»: аудитор находит их только как повод проверить настройку
(нет минус-слов, не исключена площадка, включён расширенный геотаргетинг), а расчёт эффекта
и статзначимость отдаёт аналитику (`../yandex-direct-analyst/analysis/metrics.md`).

Правки исполняет `yandex-direct` (API/XLS/браузер) — после явного «да».

---

## Железные правила

1. **Аудит по факту, не по памяти.** Каждый пункт — из слепка настроек или отчёта. Не видел
   настройку — писать «не проверено», а не «вероятно, выключено».
2. **Находка = настройка + текущее значение + почему это проблема + правка.** Без текущего
   значения это не находка, а лекция.
3. **Приоритет по деньгам, а не по длине чеклиста.** Ошибка в кампании с 3% расхода — «улучшение»,
   та же ошибка в кампании с 60% расхода — «критично».
4. **Не рекомендовать правку, у которой нет ожидаемого эффекта.** «Включить мониторинг сайта» —
   да, потому что при падении сайта показы остановятся. «Переписать все объявления» — только
   с цифрой CTR/CR, за которой стоит расчёт.
5. **Отключение площадок — крайняя мера.** Яндекс прямо предупреждает о риске потери аудитории
   (`docs/campaigns/blocked-sites.md`, `docs/general/yan.md`). Порядок и пороги — `audit/yan-placements.md`.
6. **Ничего не меняю молча.** Слепок и чтение — свободно; любая запись (`update`, `suspend`,
   правка списка запрещённых площадок) — после явного согласия и с бэкапом `get` до правки.
7. **Данные аккаунта — не для скилла.** Домены, названия кампаний, номера аккаунтов и токены
   не попадают в файлы скилла и в репозиторий.

## Workflow аудита

1. **Рамка.** Что за бизнес, что считается конверсией, KPI (CPA/ДРР), гео, сезонность,
   какие кампании в фокусе. Без этого аудит превращается в пересказ чеклиста.
2. **Доступ.** Токен API (лучше всего) либо выгрузки + скриншоты настроек. Что именно нужно —
   раздел «Данные для аудита» ниже.
3. **Слепок.** `audit/collect.py` — один JSON со всеми настройками. Дальше работа идёт по нему,
   а не по интерфейсу: воспроизводимо и дёшево по токенам.
4. **Статистика на 28–90 дней** — расход, конверсии, CPA по кампаниям; отчёты по площадкам,
   поисковым запросам, устройствам, гео. Нужна, чтобы взвесить находки деньгами.
5. **Прогон по чеклисту** (`audit/settings-checklist.md`) — механически, по всем уровням.
6. **Площадки РСЯ** (`audit/yan-placements.md`) — отдельным блоком, со своими порогами.
7. **Отчёт** (`audit/report-template.md`): резюме → находки по приоритету → план правок →
   что домерить и когда.
8. **Исполнение** — только после «да», через `yandex-direct`, с бэкапом до правки.

## Данные для аудита

Минимум (аудит настроек):
- **Токен API Директа** с доступом к аккаунту + логин клиента. Даёт всё остальное автоматически.
- Если токена нет: XLS-выгрузка кампаний, скриншоты параметров каждой кампании, список целей Метрики.

Чтобы взвесить находки деньгами (сильно повышает ценность):
- Доступ к Метрике или выгрузка Мастера отчётов за 28–90 дней по кампаниям.
- Отчёт по площадкам (срез **Название площадки**, только сети).
- Отчёт «Поисковые запросы» за 30–90 дней.

От бизнеса:
- Целевой CPA/ДРР, средний чек, маржа.
- Какая цель Метрики — деньги; учитываются ли звонки и офлайн-продажи.
- Гео и сезонность, что нельзя трогать (бренд, акции, приоритетные направления).

Чего не прошу и не принимаю: пароли от аккаунта, платёжные данные. Токен пользователь
выпускает сам и отзывает после работ.
