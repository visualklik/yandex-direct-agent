# Аудит настроек Яндекс Директа

Третий скилл в связке:

| Скилл | Вопрос, на который отвечает |
|---|---|
| `yandex-direct` | как настроить и создать |
| `yandex-direct-analyst` | что говорят цифры |
| **`yandex-direct-audit`** | **что настроено неправильно и что с этим делать** |

Разделение простое: аналитик смотрит в статистику, аудитор — в конфигурацию. Пересечение одно
— «сливающие срезы»: аудитор находит их только как повод проверить настройку
(нет минус-слов, не исключена площадка, включён расширенный геотаргетинг), а расчёт эффекта
и статзначимость отдаёт аналитику (`../yandex-direct-analyst/analysis/metrics.md`).

Правки исполняет `yandex-direct` (API/XLS/браузер) — после явного «да».

## Железные правила

1. **Аудит по факту, не по памяти.** Каждый пункт — из слепка настроек или отчёта. Не видел
   настройку — писать «не проверено», а не «вероятно, выключено».
2. **Находка = настройка + текущее значение + почему это проблема + правка.** Без текущего
   значения это не находка, а лекция.
3. **Приоритет по деньгам, а не по длине чеклиста.** Ошибка в кампании с 3% расхода — «улучшение»,
   та же ошибка в кампании с 60% расхода — «критично».
4. **Не рекомендовать правку, у которой нет ожидаемого эффекта.** «Включить мониторинг сайта» —
   да, потому что при падении сайта показы остановятся. «Переписать все объявления» — только
   с цифрой CTR/CR, за которой стоит расчёт.
5. **Отключение площадок — крайняя мера.** Яндекс прямо предупреждает о риске потери аудитории
   (`docs/campaigns/blocked-sites.md`, `docs/general/yan.md`). Порядок и пороги — `audit/yan-placements.md`.
6. **Ничего не меняю молча.** Слепок и чтение — свободно; любая запись (`update`, `suspend`,
   правка списка запрещённых площадок) — после явного согласия и с бэкапом `get` до правки.
7. **Настройку искать на всех уровнях, где она может лежать.** Цель бывает внутри стратегии,
   а не в `PriorityGoals`; минус-слова — в группах или в библиотеке, а не в кампании.
   Ложная находка обесценивает весь отчёт сильнее, чем пропущенная. Разбор типовых
   ловушек — `audit/settings-checklist.md`, раздел 8.
8. **Данные аккаунта — не для скилла.** Домены, названия кампаний, номера аккаунтов и токены
   не попадают в файлы скилла и в репозиторий.

| Файл | Что |
|------|-----|
| `audit/settings-checklist.md` | Главный чеклист: ошибка → как обнаружить → правка. По уровням: аккаунт, кампания, группа, ключи, объявления, аналитика |
| `audit/yan-placements.md` | Фильтрация площадок РСЯ: методика, лимиты, пороги, разбор мифа о «мусорных площадках» |
| `audit/api-collect.md` | Как снять слепок через API: проверенные имена полей, готовые запросы |
| `audit/collect.py` | Скрипт: снимает слепок аккаунта в JSON (кампании, группы, ключи, объявления, корректировки) |
| `audit/checks.py` | Скрипт: механические автопроверки по слепку, находки с приоритетом |
| `audit/placements.py` | Скрипт: из отчёта по площадкам считает кандидатов на запрет с проверкой порога |
| `audit/anomalies.md` | Каталог аномалий: правило, порог, что проверять при срабатывании |
| `audit/anomalies.py` | Скрипт: ищет аномальные дни по дневным рядам аккаунта и кампаний |

| `audit/fetch.py` | Скрипт: скачивает все отчёты для аудита одной командой (кампании, дни, площадки, сегмент, тип таргетинга, устройства, пол, возраст, города, поисковые запросы) |

| `audit/report-template.md` | Формат выдачи аудита текстом |
| `audit/dashboard.md` | Принципы визуального отчёта: порядок блоков, графика, цвет, печать |
| `audit/dashboard.py` | Генератор HTML-дашборда из слепка и отчётов — один самодостаточный файл |

## Workflow аудита

1. **Рамка.** Что за бизнес, что считается конверсией, KPI (CPA/ДРР), гео, сезонность,
   какие кампании в фокусе. Без этого аудит превращается в пересказ чеклиста.
2. **Доступ.** Токен API (лучше всего) либо выгрузки + скриншоты настроек. Что именно нужно —
   раздел «Данные для аудита» ниже.
3. **Слепок настроек.** `audit/collect.py` — один JSON: кампании со стратегиями и настройками,
   группы, ключи, объявления, корректировки, быстрые ссылки. Дальше работа идёт по файлу,
   а не по интерфейсу: воспроизводимо и дёшево по токенам.
4. **Статистика за 28–90 дней.** `audit/fetch.py` качает весь набор: кампании, дни, площадки,
   Поиск/сети, устройства, пол, возраст, города, поисковые запросы. Нужна, чтобы взвесить
   находки деньгами.
5. **Автопроверки.** `audit/checks.py` по слепку — реестр проверок со статусами
   pass / warn / fail / na, балл и грейд (`audit/scoring.md`). Дальше руками по
   `audit/settings-checklist.md` то, что скрипт не покрывает, и по `audit/compliance.md`
   то, что видно только глазами.
6. **Аномальные дни.** `audit/anomalies.py` по дневным отчётам — всплески и обвалы расхода,
   скачки CPA и цены клика, обрывы конверсий. Период брать от 30 дней, лучше 60:
   на коротком ряду нормы нет. Правила — `audit/anomalies.md`.
7. **Посадочные страницы.** `audit/urls.py` — коды ответа, редиректы на главную, мягкие 404
   по каждому уникальному адресу объявлений и быстрых ссылок.
8. **Площадки РСЯ.** `audit/placements.py` и методика `audit/yan-placements.md` — со своими
   порогами значимости, отдельно от остального.
9. **Отчёт.** Текстом — по `audit/report-template.md`; визуально — `audit/dashboard.py`:
   вердикт с оценкой → план правок → где деньги → аномальные дни → срезы эффективности → запросы →
   площадки → посадочные → настройки. Для деления запросов на брендовые и небрендовые
   передать `--brands` со списком написаний бренда, включая опечатки и латиницу.
10. **Исполнение** — только после «да», через `yandex-direct`, с бэкапом `get` до правки.

### Полный прогон

```bash
set -a && . ./.env && set +a          # DIRECT_TOKEN, DIRECT_LOGIN
S=.claude/skills/yandex-direct-audit/audit

python3 $S/collect.py --out snapshot.json
python3 $S/fetch.py --days 60 --out-dir data
python3 $S/urls.py --snapshot snapshot.json --out urls.json
python3 $S/anomalies.py --reports data --out anomalies.json
python3 $S/checks.py snapshot.json                      # находки текстом
python3 $S/dashboard.py --snapshot snapshot.json --reports data --urls urls.json \
    --anomalies anomalies.json \
    --target-cpa 500 --account "Клиент" --period "20.07 — 18.08.2026" \
    --brands "бренд,брэнд,brand" --out audit.html
```

Порядок важен только в одном месте: `urls.py` и `dashboard.py` читают `snapshot.json`,
поэтому `collect.py` идёт первым. `fetch.py` независим и может идти параллельно.
Названия отчётов уникальны в аккаунте — при повторном прогоне за тот же день менять `--tag`.

## Данные для аудита

Минимум (аудит настроек):
- **Токен API Директа** с доступом к аккаунту + логин клиента. Даёт всё остальное автоматически.
- Если токена нет: XLS-выгрузка кампаний, скриншоты параметров каждой кампании, список целей Метрики.

Чтобы взвесить находки деньгами (сильно повышает ценность):
- Доступ к Метрике или выгрузка Мастера отчётов за 28–90 дней по кампаниям.
- Отчёт по площадкам (срез **Название площадки**, только сети).
- Отчёт «Поисковые запросы» за 30–90 дней.

От бизнеса:
- Целевой CPA/ДРР, средний чек, маржа.
- Какая цель Метрики — деньги; учитываются ли звонки и офлайн-продажи.
- Гео и сезонность, что нельзя трогать (бренд, акции, приоритетные направления).

Чего не прошу и не принимаю: пароли от аккаунта, платёжные данные. Токен пользователь
выпускает сам и отзывает после работ.
