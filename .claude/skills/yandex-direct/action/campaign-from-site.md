# Кампания из сайта: конвейер

Задача: дали URL и тематику — на выходе черновик кампаний для Поиска и РСЯ с текстами,
собранными из фактов сайта, а не из воображения.

Скрипты делают детерминированную работу — обход сайта, отсев пустых фраз, проверку лимитов,
сборку файла. Тексты пишу я: это то место, где нужен смысл, а не регулярка.

Один проект — одна папка `projects/<slug>/` (см. `../../marketing-strategy/SKILL.md`).
Файлы кампании кладём в `projects/<slug>/campaigns/`, сырьё — в `data/`.

```bash
S=.claude/skills/yandex-direct/action
P=projects/<slug>

python3 $S/site_scan.py https://site.ru --out $P/data/site.json
python3 $S/keyword_volume.py --file $P/data/keywords.txt --geo 11036,11029 --out $P/data/keywords.json
python3 $S/adtext_check.py $P/campaigns/campaign.json
python3 $S/xls_build.py $P/campaigns/campaign.json --out $P/campaigns/campaign.xlsx
```

## 1. Разбор сайта — `site_scan.py`

Обходит внутренние ссылки и `sitemap.xml`, с каждой страницы снимает title, description,
заголовки, **цены**, телефоны, наличие форм и видимый текст. Запросы последовательные,
с паузой и браузерным User-Agent: параллельные пачки ловят 403 и портят разбор.

Результат — материал для офферов: что за услуги, какие параметры, какие цифры можно называть.

**Если цен на сайте нет — их нет и в объявлениях.** Скрипт честно вернёт пустой список,
и это сигнал: писать «от 2 млн ₽» нельзя, надо строить оффер на другом (опыт, число объектов,
бесплатный показ, сроки).

## 2. Семантика — `keyword_volume.py`

Фразы собираются из семантики сайта: услуги, синонимы, гео, параметры продукта,
брендовые запросы. Затем проверяются через `keywordsresearch.hasSearchVolume`.

API отвечает только «есть спрос / нет» для региона — частотности Wordstat в v5 нет.
Этого достаточно, чтобы выбросить придуманные фразы: они не дадут показов, но раздуют
структуру и испортят статистику групп.

Дальше фразы раскладываются по группам так, чтобы **под каждый кластер была своя посадочная**.
Группа без своей страницы — повод либо переиспользовать ближайшую, либо не создавать группу.

## 3. Тексты

Пишутся под кластер, из фактов сайта. Требования — `docs/moderation/technical-restrictions.md`
и `docs/moderation/ad-rules.md`:

| Элемент | Лимит |
|---|---|
| Заголовок | 56 символов, слово до 22 |
| Текст | 81 символ, слово до 23 |
| Быстрая ссылка | 30 символов, до **8 штук** на объявление |
| Описание быстрой ссылки | 60 символов |
| Уточнение | 25 символов |

Правила, которые ловит `adtext_check.py`: капс, восклицательный знак в заголовке, контакты
в тексте объявления, превосходные степени без подтверждения, дубли заголовков, ссылка без
протокола, больше 200 фраз в группе, фраза длиннее 7 слов.

Для комбинаторных объявлений — 3–5 заголовков и 2–3 текста на группу: система соберёт
комбинации сама. Один заголовок и один текст — это отказ от механики (см.
`updates/api-responsive-ads.md`).

Поиск и РСЯ пишутся **по-разному**: на Поиске заголовок отвечает на запрос, в сетях —
цепляет внимание и объясняет выгоду, потому что запроса там нет.

### Отображаемая ссылка

**Не заполняем.** Правило проекта: колонка «Отображаемая ссылка» в файле остаётся пустой,
`xls_build.py` не переносит туда значение, даже если оно попало в план, а `adtext_check.py`
выдаёт предупреждение, если поле заполнили.

### Быстрые ссылки

Справка (`docs/efficiency/quick-links.md`): **до восьми** быстрых ссылок, каждая до 30 символов,
описание до 60. В тексте ссылки и описания нельзя «!», «?», «[», «]» и эмодзи. Описания
показываются только в расширенном формате на десктопах и планшетах, но заполнять их стоит:
это дополнительное место под продающий текст, а переход по любой ссылке оплачивается
как один клик.

Две вещи из справки, которые легко пропустить:

- **XLS и Коммандер сбрасывают быстрые ссылки с уровня кампании и группы на уровень
  объявления.** Если в интерфейсе они заданы на кампанию, загрузка файла перенесёт их
  в объявления — это ожидаемое поведение, а не потеря настроек.
- В описании XLS-формата (`docs/alternative-interfaces/xls-interface.md`) стоит ограничение
  «суммарная длина заголовков не больше 66 символов». С восемью ссылками по 30 символов оно
  не сходится и, судя по всему, осталось от прежнего формата с четырьмя ссылками. `adtext_check.py`
  выдаёт на это **предупреждение**, а не ошибку: если Директ откажется принимать файл,
  сокращаем заголовки, но заранее резать восемь ссылок до четырёх смысла нет.

## 4. Проверка — `adtext_check.py`

Гоняется до сборки файла. Ошибки блокируют загрузку, предупреждения — повод перечитать.
Возвращает ненулевой код при ошибках, поэтому годится в конвейер.

## 5. Сборка файла — `xls_build.py`

Делает лист «Тексты» по формату из `docs/alternative-interfaces/xls-interface.md`:
первая строка группы несёт объявление, остальные фразы идут строками ниже с пустыми
повторяющимися колонками — так Директ понимает, что они относятся к той же группе.

Быстрые ссылки хранятся не отдельными колонками, а тремя — «Заголовки быстрых ссылок»,
«Описания быстрых ссылок», «Адреса быстрых ссылок», — где элементы разделены `||`.

**Файл — черновик под вычитку, а не готовая к публикации кампания.** Перед загрузкой:

1. Прочитать тексты глазами: факты с сайта могли устареть.
2. Сверить тематику с `docs/moderation/categories/` — для лицензируемых нужны документы.
3. Проверить посадочные (`../../yandex-direct-audit/audit/urls.py`).
4. Задать стратегию, бюджет и счётчик Метрики — их в файле нет, это настройки кампании.
5. Загрузить в Директ, посмотреть отчёт об ошибках загрузки, и только потом публиковать.

## Что конвейер не делает

- **Не придумывает факты.** Нет цен на сайте — нет цен в объявлениях; не указан материал
  стен — не пишем «каркасные дома».
- **Не оценивает объём спроса.** `hasSearchVolume` говорит «есть/нет», а не «сколько».
  Прогноз бюджета — в интерфейсе Директа.
- **Не публикует.** Загрузка файла и запуск — только руками пользователя, после «да».
