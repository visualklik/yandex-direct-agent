# Отчёты Метрики: какой под какой вопрос

Пресеты живут в `PRESETS` внутри `fetch.py`. Здесь — зачем каждый и как читать результат.
Полный список измерений и метрик — `api-notes.md`.

## Пресеты

| Имя | Измерение | Отвечает на вопрос |
|---|---|---|
| `sources` | источник трафика | откуда приходят и как ведут себя разные каналы |
| `direct` | кампания Директа | сколько визитов и конверсий дала каждая кампания **по данным Метрики** |
| `direct_days` | дата × источник | динамика по каналам, поиск дней-провалов |
| `landing` | страница входа | какие посадочные принимают трафик и как конвертят |
| `devices` | тип устройства | мобильные против десктопа |
| `geo` | город | география спроса |
| `search` | поисковая фраза | органика: с какими словами приходят |
| `browsers` | браузер | техническая совместимость, аномалии ботов |
| `days` | дата | общий ряд визитов для оценки периода |
| `goals` | — | достижения и конверсия по каждой цели за период |
| `days_goal` | дата | визиты и достижения **главной цели** по дням — ловит обрывы учёта |
| `landing_goal` | страница входа | посадочные с конверсией по главной цели |
| `health` | — | доля роботов, новых посетителей, мобильных визитов |
| `compare` | — | те же метрики за предыдущий период такой же длины |

## Главная цель

`fetch.py` выбирает её сам: самая результативная из целей, **исключая заглушки** вроде
«Посетил сайт» и «Визит больше 5 минут» — по ним конверсия близка к 100%, и любой срез
по такой цели бессмыслен. Переопределяется флагом `--goal <id>`.

## Обрывы конверсий

Полоса дней без достижений при живом трафике — главный признак сломанного учёта: форма,
счётчик или сама цель. Порог тот же, что в аномалиях Директа: полоса считается находкой,
только если за неё ожидалось не меньше трёх достижений. Без этого цель с редкими
конверсиями даёт ложные тревоги каждую неделю.

## Сверка Директа и Метрики

Главный отчёт — `direct`: разрез `ym:s:lastDirectClickOrder` даёт кампании так, как их
видит Метрика. Рядом кладётся отчёт Директа по тем же кампаниям
(`../../yandex-direct-audit/audit/fetch.py`), и цифры сравниваются.

Расхождение — норма. Ненормально, когда не понятно, откуда оно взялось. Проверять по порядку:

1. **Клики против визитов.** Клик не равен визиту: часть кликов не доезжает до сайта.
   Разница в 5–15% — обычное дело, больше — искать техническую причину.
2. **Модель атрибуции.** В Директе и в отчёте Метрики она может быть разной; сравнивать
   можно только одинаковые.
3. **Цель.** Директ считает конверсии по цели стратегии, отчёт Метрики — по той, что
   выбрали в запросе.
4. **Часовой пояс.** У счётчика и у кампаний он может отличаться — дневные ряды разъедутся.
5. **Окно.** При оплате за конверсии расход Директа относится ко дню клика, а конверсия
   в Метрике — ко дню достижения.
6. **Последние дни.** Конверсии дозаписываются, свежий хвост всегда занижен.

## Как читать выборку

В каждом сохранённом отчёте лежат `sampled` и `sample_share`. Если `sampled: true`, цифра
посчитана по части данных. В выводах это обязательно оговаривается, а при принятии решений
период сужается или запрашивается `accuracy=full`.

## Ограничения, о которые спотыкаются

- **20 метрик на запрос.** Достижения по всем целям приходится тянуть пачками;
  `fetch.py` делает это сам, по десять целей за раз.
- **Цели-заглушки искажают любой срез.** Если в счётчике есть цель «Посетил сайт»,
  её конверсия близка к 100%, и средняя по всем целям теряет смысл. Считать по конкретной.
- **Страница входа — не то же самое, что посадочная объявления.** Пользователь мог зайти
  повторно с другой страницы; для сверки с рекламой полезнее разрез по кампании.
