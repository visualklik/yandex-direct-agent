## Особенности выгрузок Директа

- Разделитель CSV чаще `;`, кодировка UTF-8 (иногда с BOM) или cp1251.
- Десятичный разделитель — запятая; в числах бывают неразрывные пробелы как разделитель тысяч (`\xa0`).
- Над таблицей — служебные строки (название отчёта, период, цель, атрибуция). **Прочитать их и зафиксировать в отчёте** — это и есть рамка анализа.
- Внизу строка «Итого» — исключать из построчного анализа, использовать как контрольную сумму.
- Прочерк `-` вместо нуля; «Другие поисковые запросы» — агрегат, не строка-объект.

`load_direct` находит строку заголовка по «Показ|Клик», отдаёт всё выше как meta, определяет разделитель (`;`/таб/запятая) и кодировку (utf-8-sig → cp1251), выбрасывает «Итого». `num` чинит `1 234,50`, `1\xa0234,50`, `-`, `12%`.

Типичные числовые столбцы: Показы, Клики, CTR (%), Расход всего, Ср. цена клика, Конверсии, Конверсия (%), Цена цели, Доход, Прибыль, Рентабельность, ДРР (%). Названия у разных выгрузок различаются — сверять по `df.columns`, не хардкодить вслепую.

Всегда после загрузки: сверить сумму «Клики»/«Расход» со строкой «Итого» исходника. Не сходится — парсер соврал, чинить до анализа.

## Пересчёт метрик из сырых столбцов

Проценты и средние из выгрузки при агрегации складывать нельзя — пересчитывать:

```python
def enrich(g):
    g["CTR"] = g["Клики"] / g["Показы"].replace(0, pd.NA) * 100
    g["CPC"] = g["Расход"] / g["Клики"].replace(0, pd.NA)
    g["CR"]  = g["Конверсии"] / g["Клики"].replace(0, pd.NA) * 100
    g["CPA"] = g["Расход"] / g["Конверсии"].replace(0, pd.NA)
    if "Доход" in g:
        g["ДРР"] = g["Расход"] / g["Доход"].replace(0, pd.NA) * 100
        g["ROI"] = (g["Доход"] - g["Расход"]) / g["Расход"].replace(0, pd.NA) * 100
    return g

agg = enrich(df.groupby("Условие показа", as_index=False)[
    ["Показы", "Клики", "Расход", "Конверсии"]].sum())
```

## Кандидаты на отключение

Статзначимость: без конверсий строка «плохая» только если кликов набрано заметно больше, чем нужно в среднем на одну конверсию.

```python
base_cr = agg["Конверсии"].sum() / agg["Клики"].sum()      # средний CR по срезу
min_clicks = 3 / base_cr                                    # порог «шум/не шум»
target_cpa = 1500                                           # KPI пользователя

waste = agg[(agg["Конверсии"] == 0) & (agg["Клики"] >= min_clicks)]
overpay = agg[(agg["Конверсии"] > 0) & (agg["CPA"] > 2 * target_cpa) & (agg["Конверсии"] >= 3)]
print(f"слив: {waste['Расход'].sum():.0f} ₽ в {len(waste)} строках "
      f"({waste['Расход'].sum()/agg['Расход'].sum()*100:.1f}% бюджета)")
```

Экономия от отключения — это верхняя оценка: часть трафика перетечёт в другие срезы, а не исчезнет. Так и писать в отчёте.

## Значимость различия двух вариантов (A/B, эксперимент)

```python
from math import sqrt, erf

def ztest(c1, n1, c2, n2):
    """Конверсии/клики двух вариантов -> (разница CR в п.п., p-value двусторонний)."""
    p1, p2 = c1 / n1, c2 / n2
    p = (c1 + c2) / (n1 + n2)
    se = sqrt(p * (1 - p) * (1 / n1 + 1 / n2))
    if se == 0:
        return 0.0, 1.0
    z = (p1 - p2) / se
    pv = 2 * (1 - 0.5 * (1 + erf(abs(z) / sqrt(2))))
    return (p1 - p2) * 100, pv

print(ztest(40, 1200, 28, 1150))
```

p ≥ 0.05 → «разница не подтверждена», не «варианты равны». Для экспериментов Директа сверяться с `docs/campaigns/experiments.md` (деление трафика, длительность, одинаковые настройки кроме тестируемого).
