# Формат выдачи: разбор и аудит

Правило: сначала вывод, потом цифры, в конце — что делать. Не пересказывать таблицу словами; таблица говорит сама.

## Короткий разбор (1 вопрос — 1 ответ)

```
Вывод: <одно предложение — что происходит и почему>

Рамка: период 01–28.07.2026 vs 03–30.06.2026 · цель «Заявка» · атрибуция «Последний значимый» · Поиск+РСЯ

Цифры:
| Метрика | Период A | Период B | Δ |
|---|---|---|---|
| Расход | | | |
| Клики / CPC | | | |
| Конверсии / CR | | | |
| CPA | | | |
| Доход / ДРР | | | |

Что нашёл:
1. <срез> — <факт с числом> (доля расхода X%)
2. ...

Что сделать:
| Приоритет | Правка | Ожидаемый эффект | Риск |
|---|---|---|---|

Чего не хватает для точного вывода: <данные / период>
```

## Полный аудит аккаунта

1. **Резюме** — 3–5 пунктов: где деньги, где слив, главный рычаг. Числа обязательны.
2. **Рамка и качество данных** — период, цели, атрибуция, что учитывается некорректно (нет коллтрекинга, не передаётся доход, цели-микро).
3. **Экономика** — расход, конверсии, CPA, доход, ДРР/ROI против KPI пользователя. Отдельно: бренд vs небренд, Поиск vs РСЯ, новые vs повторные.
4. **Структура и настройки** — типы кампаний, стратегии и их ограничения, бюджеты, обучение (конверсий/нед), корректировки, гео, расписание. Сверка с `docs/efficiency/check-list.md`.
5. **Трафик** — топ-срезы по расходу; сливающие строки (со статзначимостью); мусорные поисковые запросы и доля их расхода; автотаргетинг vs фразы; площадки.
6. **Объявления и посадочные** — CTR по объявлениям в группе, отказы, соответствие запрос → страница.
7. **Аналитика и учёт** — Метрика, цели, ценность конверсий, UTM, офлайн-конверсии, расхождения с CRM.
8. **План правок** — таблица: правка · ожидаемый эффект (в ₽ или % где считается) · усилие · риск · как проверим. Сортировка по эффект/усилие. Явно помечать необратимые шаги.
9. **План измерений** — что домерить, какой отчёт, когда пересмотреть (с учётом обучения и окна атрибуции).

## Требования к формулировкам

- Каждое утверждение — с числом и указанием среза, иначе это мнение, а не анализ.
- Оценка эффекта правки — диапазон и оговорка «верхняя оценка, часть трафика перетечёт».
- Недостаточные данные помечать явно: «конверсий 4 — в пределах погрешности, вывода нет».
- Разделять факт (из выгрузки), интерпретацию (моя гипотеза) и рекомендацию (действие).
- Ссылаться на справку там, где правило неочевидно: путь к файлу `docs/...` + `source:` URL.
- Исполнение правок — скилл `yandex-direct`, после явного «да». Пополнение счёта и платёжные данные — пользователь сам.
