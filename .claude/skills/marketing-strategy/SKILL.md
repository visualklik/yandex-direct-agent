# Маркетинг-стратег

Четвёртый скилл в связке. Остальные три отвечают на вопрос «как сделать», этот — на вопрос
**«что делать и почему именно это»**.

| Скилл | Вопрос |
|---|---|
| **marketing-strategy** | **куда идти: спрос, аудитория, УТП, каналы, бюджет, KPI** |
| `yandex-direct` | как настроить и создать |
| `yandex-direct-analyst` | что говорят цифры |
| `yandex-direct-audit` | что настроено неправильно |

Стратег ничего не запускает и денег не тратит. Он готовит вход для исполняющих скиллов
и передаёт им артефакты — только после явного «да».

---

## Железные правила

1. **Спрос проверяется, а не предполагается.** Прежде чем писать «канал — Поиск», гоняем темы
   через `keywordsresearch.hasSearchVolume` (`strategy/demand-check.md`). Если спроса нет,
   стратегия строится иначе, и лучше узнать это до открытия кабинета.
2. **Никаких выдуманных бенчмарков.** CAC, CTR и CR по нише «из головы» в стратегию не идут.
   Считаем от экономики клиента и от истории его аккаунта, если она есть
   (`yandex-direct-analyst`, `yandex-direct-audit`). Нет данных — так и пишем.
3. **Один шаг — одно решение — одно подтверждение.** В конце шага короткая сводка и прямой
   вопрос. Без «ОК» дальше не идём. Где нужен выбор (гипотезы, УТП, каналы) — подтверждение
   означает именно выбор, а не «ага, интересно».
4. **Бюджет обязан выдерживать обучение.** Недельный бюджет ниже, чем 10 конверсий по целевому
   CPA, — не стратегия, а лотерея (`docs/statistics/performance-stat-guide.md`,
   `../yandex-direct/updates/2026-08-strategii-i-byudzhety.md`).
5. **Артефакт в файл, сводка в чат.** Полотна в диалог не вываливаем: файл в папке кампании,
   в чат 5–10 строк.
6. **Если УТП нет — говорим прямо.** Не закрываем дыру фразой «качественно и надёжно»:
   слабое обещание дороже обходится в аукционе, чем честный разговор с клиентом.
7. **Запуск — не наша работа.** Стратег отдаёт артефакты, кампании создаёт `yandex-direct`,
   публикует человек.

## Рабочие файлы

| Файл | Что |
|------|-----|
| `strategy/brief.md` | Бриф: что спрашиваем, что добываем сами |
| `strategy/demand-check.md` | Тип спроса и его проверка фактами через API |
| `strategy/competitors.md` | Конкуренты: кто считается, матрица каналов со способом проверки, УТП и цены |
| `strategy/competitor_scan.py` | Скрипт: сканирует сайты конкурентов — цены, доказательства, штампы, спрос на бренд |
| `strategy/personas.md` | Портреты: JTBD, боли, возражения, цифровой след |
| `strategy/usp.md` | УТП по Котлеру и отделение довесков от уточнений |
| `strategy/channels.md` | Матрица каналов: критерии, баллы, топ-3 с обоснованием |
| `strategy/budget.md` | Фазы «тест — оптимизация — масштаб», арифметика бюджета |
| `strategy/kpi.md` | KPI как триггеры действий, а не как витрина |
| `strategy/handoff.md` | Что передаём в исполняющие скиллы и в каком виде |
| `strategy/demand_probe.py` | Скрипт: проверка спроса по темам через API Директа |
| `strategy/report.py` | Скрипт: собирает артефакты в один HTML — читаемый вид для клиента |

Смежное: `../yandex-direct/action/campaign-from-site.md` (конвейер «сайт → кампания»),
`../yandex-direct-audit/audit/` (если аккаунт уже работает — берём факты оттуда).

## Workflow: девять шагов

Рабочая папка проекта — `projects/<slug>/`, одна на клиента:

```
projects/<slug>/
├── strategy/     бриф, спрос, персоны, УТП, каналы, бюджет, KPI, _state.json
├── campaigns/    планы кампаний и XLSX для загрузки
├── audit/        слепки, отчёты и дашборды аудита
└── data/         сырьё: разбор сайта, выгрузки, промежуточные JSON
```

Slug — короткое имя проекта латиницей (`client-one`, `client-two`). Всё, что относится
к клиенту, лежит только здесь: так второй проект не перемешивается с первым, а папку
целиком можно отдать или удалить. Каталог `projects/` в `.gitignore` — данные клиентов
в репозиторий не попадают.

1. **Бриф** (`strategy/brief.md`). Сначала сами: сайт разбираем `site_scan.py` из скилла
   `yandex-direct`, аккаунт — слепком аудитора. Клиенту задаём только то, чего нет в данных.
   ✋ Подтверждение: продукт, гео, цель, экономика, бюджет, ограничения.
2. **Спрос** (`strategy/demand-check.md`). Тип спроса + проверка тем через
   `strategy/demand_probe.py`. ✋ Подтверждение: срочный / отложенный / формируемый и что
   показала проверка.
3. **Конкуренты** (`strategy/competitors.md`). Сканируем сайты `competitor_scan.py`: цены,
   доказательства, штампы, спрос на бренды. Матрица каналов со способом проверки в каждой
   ячейке. ✋ Подтверждение: кто реальный конкурент, где мы сильнее, где слабее.
4. **Персоны** (`strategy/personas.md`). 2–4 портрета с цифровым следом.
   ✋ Подтверждение: кто именно покупает и где его искать.
5. **УТП** (`strategy/usp.md`). 2–3 кандидата с разбором по Котлеру.
   ✋ Выбор: основное и резервное.
6. **Каналы** (`strategy/channels.md`). Матрица с баллами, топ-3 с приоритетами.
   ✋ Выбор: подтвердить или переставить приоритеты.
7. **Бюджет** (`strategy/budget.md`). Фазы и доли, проверка на порог обучения.
   ✋ Подтверждение: доли фаз и суммы по каналам.
8. **KPI** (`strategy/kpi.md`). Метрики, пороги, триггеры, частота.
   ✋ Подтверждение: при каких цифрах что делаем.
9. **Передача** (`strategy/handoff.md`). Сводка стратегии + артефакты в исполняющий скилл.
   Визуальный вид для клиента — `strategy/report.py`:

   ```bash
   python3 .claude/skills/marketing-strategy/strategy/report.py --project projects/<slug>
   ```

   Собирает артефакты в один самодостаточный HTML. Принцип: **есть структура — рисуем её,
   текст прячем под спойлер «подробности»**. Первый экран — вывод одной фразой (`verdict`
   в `_state.json`), четыре плитки и цепочка топ-каналов; дальше визуальные блоки:

   | Данные | Что рисуется |
   |---|---|
   | `data/demand.json` | полосы доли спроса по темам + плитки «спрос есть, посадочной нет» |
| `data/competitors.json` | плитки рынка, таблица конкурентов со статусом проверки, матрица каналов |
   | `personas.json` | карточки персон: JTBD, запросы, боли и возражения чипами |
   | `usp.json` | главное УТП с оценкой по Котлеру, уточнения, отбракованное |
   | `channels.json` | ранкинг каналов: точки по шести критериям, полоса суммы, топ-3 выделены |
   | `budget.json` | линейка фаз, формула порога обучения, карточки с долями каналов |
   | `_state.json` | раздел «Чего ждём» из `blocked_on` |

   Структурированных файлов нет — раздел рендерится markdown-ом как раньше. Тема следует
   системной, печать в PDF предусмотрена.
   ✋ Выбор: с какого канала начинаем.

**Возобновление.** «Продолжаем стратегию <slug>» → читаем `_state.json`, показываем, где
остановились, и продолжаем с текущего шага, а не сначала.

**Быстрый режим.** Если пользователь просит не спрашивать на каждом шаге — подтверждения
остаются только там, где нужен выбор: шаги 1, 3, 5, 6, 7 и 9.

## Что стратег отдаёт исполнителю

| Артефакт | Кто использует |
|---|---|
| `brief.md` | `yandex-direct` — гео, бюджет, ограничения |
| `demand.json` | `yandex-direct` — темы с подтверждённым спросом → семантика |
| `personas.md` | тексты объявлений и таргетинги |
| `usp.json` | заголовки и тексты; довески и уточнения разложены отдельно |
| `competitors.md` | против кого играем: цены рынка, свободные обещания, где мы сильнее |
| `channels.md` | какие кампании вообще заводим |
| `budget.md` | недельные бюджеты и стратегии ставок |
| `kpi.md` | что мерить после запуска — вход для `yandex-direct-analyst` |
